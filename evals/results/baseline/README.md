**Дата:** 2026-09-23.
**Модель:** `claude-haiku-4-5` (Claude Code 2.1.281, headless).
**Середовище:** `baseline` (див. [TEST_PLAN, розділ 4](../../../docs/TEST_PLAN.md#4-середовища-для-агентних-тестів)): стандартний Claude Code без навичок користувача й без MCP. Дозволені інструменти: Bash, Read, Write, Edit, Glob, Grep, WebFetch, WebSearch.
**Запити:** 3 приклади із завдання ([`evals/cases.yaml`](../../cases.yaml)). По 1 прогону; це точка відліку, а не статистика.

Мета — побачити, що модель робить **сама**, щоб потім показати, що саме змінює навичка.

## Ключові спостереження

1. **Модель не знає, як дістати дані.** Жоден прогін не звернувся до Wikimedia Analytics API, хоча Bash і WebFetch були доступні. У `fasting-pl-cs` модель навіть пише неправду, що API «вимагає прямого звернення до них».
2. **Галюцинації замість даних.**
   - «Глобальний тренд — зростання інтересу до інтервального голодування» не має жодного джерела.
   - Назви статей вигадано.
   - У `english-learning-report` рейтинг побудовано на випадкових маркетингових оглядах. Тон впевнений, оцінки довіри немає.
3. **Пастку в прикладі 1 не помічено.** У польській Wikipedia **немає** окремої статті про інтервальне голодування: у Wikidata Q1666254 немає `plwiki`, а «post przerywany» — лише червоне посилання. Модель цього не з'ясувала. Коректна відповідь мала б прямо це сказати.
4. **Мова ≠ країна.** «Португальський розділ» підмінено на «Португалія/Бразилія» як ринки без жодного застереження.
5. **Немає звіту, яким можна поділитися.** Прохання «підготуй короткий звіт» виконано як текст у чаті.
6. **Витрати без результату.** Найдорожчий прогін ($0.34, 17 викликів) не дав жодного числа.

## Що з цього випливає для навички

| Проблема baseline | Рішення в навичці |
|---|---|
| Не знає API, вгадує URL | Детермінований CLI `scripts/wir`: API, User-Agent, кеш, кодування назв |
| Вигадує назви статей | Мапінг через Wikidata (QID → sitelinks); відсутня стаття = явний статус `missing` |
| Числа з повітря | Числа дає лише CLI; `report` робить fact-check тексту агента проти `study.json` |
| Немає оцінки довіри | Індекс довіри з поясненням причин (сезонність, сплески, боти, нормалізація) |
| Мова ≠ країна | Топ країн читачів розділу (`top-by-country`) у виводі + обов'язкове застереження |
| Немає артефакту | PDF на 1 сторінку + CSV + PNG |
| Багато кроків і токенів | Одна команда `study new` → компактне резюме ≤ 3 000 символів |

## Урок з першої спроби (важливо для методології)

Перша спроба baseline **була забруднена** і її відкинуто. Робоча тека прогону лежала всередині репозиторію, і Haiku через `cd ..` дістався до `SKILL.md`, `README.md` та `evals/cases.yaml`. У цьому файлі в полях `notes` записані очікувані відповіді.

Виправлення в [`evals/claude_code.py`](../../claude_code.py):
- кожен прогін іде в тимчасовій теці **поза репозиторієм**;
- у середовищах `clean` та `realistic` агент отримує **лише пакет навички**: `SKILL.md`, `scripts/`, `src/`, `references/`, `assets/`, lock-файли. Без `evals/`, `docs/`, `tests/`.

Пакування одразу виявило реальний баг: `pyproject.toml` посилався на `README.md`, якого немає в пакеті. Навичка, встановлена в користувача, не запустилася б. Баг виправлено, додано регресійний тест `test_packaged_skill_runs_without_dev_files`.
